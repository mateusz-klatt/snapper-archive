# Backstop only — see SNAPPER_ALERT_EMAIL below for the real alert channel.
# The scripts redirect their own output, so cron mails only what happens BEFORE
# that redirect: a missing file, a syntax error, a failed exec, an OOM kill.
MAILTO="root"

# Installation-specific values. Replace every placeholder before installing
# this crontab. SNAPPER_ARCHIVE_ROOT is explicit here for operational clarity;
# the scripts can otherwise derive it from their location. Crontab assignments
# are exported to each job automatically; shell-style `export` is not valid here.
SNAPPER_ENV_FILE="/absolute/path/to/private/database.env"
SNAPPER_ARCHIVE_ROOT="/absolute/path/to/snapper-archive"
SNAPPER_APP_ROOT="/absolute/path/to/snapper"
SNAPPER_DB_HOST_FROM="host-as-written-in-DB_URL"
SNAPPER_DB_HOST_TO="host-reachable-from-cron-host"
SNAPPER_GITLINK_REMOTES="origin secondary-mirror"
# Where failure alerts are mailed. Leave unset to keep every job log-only.
#
# This is NOT a substitute for MAILTO, and MAILTO is not a substitute for it —
# they catch different failures. Every script in bin/ runs `exec >>"$LOG" 2>&1`
# on startup, so cron has no output to mail for anything that happens after that
# line: a job can fail every night in total silence, and one did for two weeks.
# The scripts therefore mail their own failures explicitly, through this address.
# MAILTO below then remains as the backstop for what a script cannot report
# itself — missing file, syntax error, a failed `exec`, an OOM kill.
#
# "root" resolves through /etc/aliases (msmtp expands it when msmtprc sets
# `aliases /etc/aliases`). Naming the alias rather than a person keeps the real
# destination in exactly one place on the host, and keeps this file free of a
# personal address. Cron does NOT expand variables in this block, so MAILTO
# cannot reference this value — both are written literally.
SNAPPER_ALERT_EMAIL="root"

# Snapper data retention. Logs: ${SNAPPER_ARCHIVE_ROOT}/logs/
#
# TIMEZONE: Ubuntu cron 3.0pl1 does NOT honour CRON_TZ (a cronie/Red Hat
# extension absent from this build -- see /usr/share/doc/cron/FEATURES:
# "TZ can be set, but cron ignores it ... passing it on through to the
# commands it runs"). Schedule times below are therefore ALWAYS system
# local time (Europe/Warsaw). This is intentional and safe:
#   - the retention WINDOW is computed with `date -u` inside the scripts,
#     so eligibility is DST-independent regardless of when cron fires;
#   - 03:17 / 04:30 local sit OUTSIDE the 02:00-03:00 DST switch window,
#     so no fire is ever doubled or skipped across a clock change;
#   - flock + manifest idempotency + 3-day catch-up backstop any miss.
# If a guaranteed-UTC fire time is ever required, convert to a systemd
# timer with `OnCalendar=*-*-* 03:17:00 UTC` (cron cannot express it).
#
# Daily 05:00 local: Polygon ingest in two phases — fetch (rate limited to
# ~12s/symbol, 2-3h for ~593 symbols, API+disk only) then load (writes candles).
# 05:00 because the daily flat files only exist after midnight UTC, and because
# it puts the DB-writing phase around 07:00-08:00, clear of the 03:17 retention
# job — the two would otherwise contend on the candles table.
0 5 * * * "${SNAPPER_ARCHIVE_ROOT}/bin/polygon-daily.sh"
# Daily 03:17 local: export+purge every tick day that fell out of the configured horizon.
17 3 * * * "${SNAPPER_ARCHIVE_ROOT}/bin/retention-daily.sh"
# Weekly Sun 04:30 local: sweep closed SCD2 candle versions across the full history.
30 4 * * 0 "${SNAPPER_ARCHIVE_ROOT}/bin/retention-weekly-candles.sh"
# Daily 12:17 local: renew the forward window of daily partitions and report
# DEFAULT occupancy. Nothing renewed partitions at all until this job existed;
# the leaves that were there came from the migration that created them.
#
# Midday, not night, and clear of BOTH neighbours on purpose. The 03:17
# retention job holds ACCESS EXCLUSIVE on the ticks parent while it counts a
# multi-million-row leaf, and the 05:00 polygon job writes candles until roughly
# 08:30; the partition tool takes that same parent lock with a 2s timeout, so an
# overlap would fail it for no reason. The hour is otherwise free: a 14-day
# forward window makes coverage independent of when the job fires.
17 12 * * * "${SNAPPER_ARCHIVE_ROOT}/bin/partitions-daily.sh"
